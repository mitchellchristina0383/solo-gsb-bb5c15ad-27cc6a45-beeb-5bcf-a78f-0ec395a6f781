📮 邮件投递路径检查器

粘贴邮件原始头部（含 Received 字段），自动展开折行、按实际投递顺序排列中继节点并计算相邻节点耗时。 顺序自上而下为：发件方 → 收件方。在 A、B 两侧各粘贴一份头部，可对照两份邮件的投递路径差异。

单侧输入上限 {{ max_input_kb }} KB（MAX_INPUT_KB）

“下载脱敏报告”基于当前“头部 A”内容，调用 POST /api/analyze/share： 主机名与 IP 按投递顺序替换为本次请求内稳定的 H1 / IP1 等别名， 仅导出路径序号、别名、UTC 时间、相邻耗时与异常说明，不含原始头部、邮件摘要或 Received ID。

🔏 ARC 链结构检查

粘贴含 ARC 字段的邮件原始头部，系统按 i 标签把 ARC-Seal / ARC-Message-Signature / ARC-Authentication-Results 归组为 ARC 实例并校验： 每个实例须三类字段各一条、实例号从 1 开始连续；首个实例（i=1）的 Seal cv 须为 none，后续实例须为 pass。 折行与标签书写顺序不影响识别；非法 i、字段重复 / 缺失、跳号、 cv 异常会逐项定位。完全没有 ARC 字段时报告“无 ARC 链”，不判定通过。

也可调用 POST /api/arc/check（JSON：{"headers": "..."}）

✍️ DKIM 头字段覆盖审计

粘贴含 DKIM-Signature 的邮件原始头部，系统复用同一套折行展开， 逐条读取每条签名的 h= 列表，并独立地按列表顺序、 从头部底部向上为同名项匹配尚未使用的实际字段（重复字段名不按集合合并， 依据 RFC 6376）。展示每条签名的匹配结果与字段位置、未匹配的 h= 项， 以及 From / Subject / To / Date 中未被该签名覆盖的实际副本。无签名时单独报告；缺失或空 h= 标为异常。 结果只表示字段覆盖，不宣称签名真伪。

也可调用 POST /api/dkim/coverage（JSON：{"headers": "..."}）

🔗 接收链可信边界（单封邮件）

粘贴单封邮件的原始头部，并填写本组织接收服务器主机名名单（每行一个， 忽略大小写与末尾点）。系统复用同一套 Received 解析，从头部最上方 （最终接收服务器最新追加的一条）开始向下逐跳检查 by 主机名： 只有自顶端连续命中名单的跳才标为可信，首个未命中或缺少 by 的跳即为可信边界；边界之后即使再命中名单也 不会重新接入。页面展示每跳可信状态、边界位置，以及最后可信跳 记录的 from 主机与对端 IP（外部交接点）。顶端未命中或没有 Received 时明确提示无法建立可信链。

也可调用 POST /api/analyze/trust-boundary（JSON：{"headers": "...", "trusted_hosts": ["..."]}）

🛡️ 认证结果来源（Authentication-Results 归属）

粘贴单封邮件的原始头部，并填写本组织接收服务器主机名名单（每行一个， 忽略大小写与末尾点）。系统复用折行展开与可信边界分析，把每条 Authentication-Results 归属到其后紧邻的 Received（两者之间不得有另一条 Received）： 仅当该跳属于自顶端连续可信前缀、且 authserv-id 与该跳 by 主机一致时，才标为本组织声明；其余逐条标明 无对应跳 / 越过边界 / 身份不符。对本组织声明提取 spf / dkim / dmarc 结果词， 按原文顺序展示并保留重复声明；没有可信前缀时明确显示无本组织声明。

也可调用 POST /api/analyze/auth-results（JSON：{"headers": "...", "trusted_hosts": ["..."]}）
